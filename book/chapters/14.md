# 第 14 章：Coding Agent 的代码仓库理解能力

> **正文初稿 v0.1，待技术审稿** · 第三篇：真实场景 Agent  
> 本章在可信本地目录上实现只读 Python AST 索引。它不是完整的 LSP/编译器索引，更没有运行未知仓库代码的权限。

## 14.1 为什么 Coding Agent 先需要理解代码库？

Coding Agent 不能只根据文件名猜测修复位置。真实代码库通常拥有大量文件、符号、依赖以及动态调用关系。任务开始阶段需要回答：哪些文件负责目标行为？哪些函数与接口有关？修改可能影响哪些测试？如果把整个仓库全部放进 Prompt，会遇到 Context 成本和检索噪声问题。

## 14.2 Repository Map

Repository Map 是一个紧凑、可导航的代码结构视图，通常包含文件、类、函数、定义位置以及必要的依赖信息。它不是全部源代码，也不是任务完成的证明。

本章索引结果示例：

~~~text
app.py
  3: class Service
  4: function Service.run
helpers.py
  1: function item
~~~

在大型代码库中可以按任务相关性选取地图片段，并结合第 8 章 Context Manager 限制大小。

## 14.3 Grep、AST 与 LSP 的分工

| 方法 | 擅长 | 限制 |
| --- | --- | --- |
| Grep/全文搜索 | 精确错误消息、标识符、日志字符串 | 不能理解符号绑定 |
| AST | 解析语言结构、符号定义、语法级 Import | 无法独立完成类型解析和动态绑定 |
| LSP | Go-to-definition、References、类型与诊断 | 依赖语言服务器及项目配置 |
| Embedding Search | 语义相关代码召回 | 可能漏掉精确符号和调用关系 |

从零构建 Coding Agent 时建议先实现稳定的文件读取、Grep 与 AST，然后根据语言引入 LSP、Tree-sitter、类型检查和多仓库依赖分析。Python AST 无法解析 Rust、Java 等语言。

## 14.4 AST 索引

本章使用 Python 标准库 ast.parse，仅进行静态解析，不 import 仓库模块，也不运行代码。

~~~python
tree = ast.parse(source)
for node in ast.walk(tree):
    ...
~~~

实际源码：[RepositoryIndex](../../src/mini_agent/repository_index.py)。它提取 Python 的 ClassDef、FunctionDef、AsyncFunctionDef 和 Import / ImportFrom，并保留文件路径、行号和嵌套限定名。

这是语法结构索引，不是完整调用图。例如函数中的动态 getattr、依赖注入、反射、条件导入和猴子补丁都可能改变实际调用目标。

## 14.5 安全读取与路径边界

读取不可信仓库时，不能未经控制遍历整个磁盘或解析无限大的文件。本章限定根目录、只读取 .py 文件、跳过符号链接及常见隐藏/缓存目录，对单文件大小和最大文件数设置限制，遇到非法 UTF-8 或 SyntaxError 则跳过。

但这是教学级防护：并发替换文件、文件系统挂载、特殊文件和路径竞态还需要更强的沙箱与系统级访问控制。**不应把遍历限制误认为安全沙箱。**

## 14.6 代码检索

本章的 search 是不执行代码的简单 case-insensitive Literal Search。对于精确错误字符串和函数名很实用；生产中可采用 ripgrep 和语言服务器，但需要将 Shell 执行的权限与资源限制交给第 7、18 章的 Tool Runtime/Sandbox。

引用结果必须提供文件路径和行号，避免模型仅凭某段脱离上下文的文字生成修改建议。

## 14.7 依赖图和调用图

静态 Import 列表能够展示模块依赖的部分结构。要构建更可靠的跨模块引用或调用图，应处理相对 Import、包结构、别名、作用域、继承、动态分派和类型信息。AST 中出现一个函数调用名并不等价于确定最终运行时调用的目标。

因此本章不会把它的 Import 列表称作“准确依赖图”，也不声称已经实现全功能 Call Graph。

## 14.8 与 Context Engineering 的集成

真实 Coding Agent 可以使用：

~~~text
Task -> Repo Map -> Keyword/AST Search -> Select Files
     -> Context Budget -> Model -> Tool Use -> Verify
~~~

首先用 Repository Map 缩小范围，再读取与问题相关的文件和测试；不要无条件把所有文件拼入模型上下文。

尤其要保持仓库代码为**非可信输入**。README 和代码注释里的“忽略系统规则”不应被提升为运行权限。

## 14.10 生产版继续需要什么？

要将本实现升级为多语言 Coding Agent Repository Intelligence，需要：

- Tree-sitter / LSP / Java Language Server 等多语言解析器；
- Incremental Index 和工作树/提交版本一致性；
- Gitignore 与权限策略；
- 跨模块准确的引用和类型解析；
- 源代码安全与敏感信息筛选；
- 图检索、语义检索和多阶段重排序；
- 大规模单体仓库的并发索引；
- Token 预算控制、片段级证据引用与更新；
- 真实 Coding Benchmark 测试定位效果。

## 14.11 课后练习

1. 将当前 Import 列表解析成仓库内部模块图，并正确处理相对导入。
2. 为 Python 函数调用建立不保证完全正确的静态候选 Call Graph，并标注不确定性。
3. 用 Tree-sitter 支持 Rust 与 Java。
4. 增加基于 Git 变更记录的增量索引。
5. 设计代码片段重排与 Context Window 预算。
6. 用一个真实 Bug 修复数据集评价定位 Recall@K。
7. 增加文件时间戳与哈希，检查索引和工作树是否一致。
8. 对路径逃逸和链接替换设计安全测试。

## 14.12 总结

Coding Agent 的仓库理解首先来自可靠的文件发现、结构解析、符号位置和可追溯检索，然后逐步扩展到跨语言 LSP、依赖图、语义检索与增量更新。**找到代码不是修复完成**；最终仍需第 10 章 Verifier 与后续 Coding Agent 的执行闭环。
