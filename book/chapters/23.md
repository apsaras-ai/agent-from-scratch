# 第 23 章：Agent Performance 与 Cost Optimization

> **正文初稿 v0.1，待技术审稿** · 第四篇：生产级 Agent Runtime 与 Infrastructure。  
> **实验**：完全离线的 Token Cost、DAG Critical Path、Cache Scope、Budget/Quality Gate 和方案比较。价格与耗时是显式**合成参数**，不是任何厂商的实时定价或真实模型性能。

## 学习目标

读者应能分析 Agent 的全链路延迟、Token 和工具成本，识别关键路径，评估缓存和并行化，实施可审计的预算控制，并在**独立验收条件不下降**的前提下比较优化方案。

## 23.1 优化目标：不只是“少花 Token”

Agent 任务可能多轮调用模型、工具、沙箱和外部 API。降低模型请求次数不一定降低端到端成本：失败重试、错误修复、人工审核和缺乏验证造成的损失也应纳入预算。

真实优化目标是：

\[
\min_{\pi}\ E[C_{\mathrm{total}}(\pi)]
\quad\text{subject to}\quad
P(\mathrm{verified\ success}\mid\pi)\ge q_{\min},
\quad P99(T_\pi)\le T_{\max}.
\]

这里 \(\pi\) 是执行策略，\(q_{\min}\) 是任务级质量门槛。**质量门槛应由独立 Verifier 和固定任务集测量，不能把模型自报完成当成成功。**

## 23.2 成本拆解

一次任务总成本至少可能包含：

- 模型 Input/Output/Cached Tokens；
- 搜索、浏览器、代码执行、API 请求费用；
- 沙箱 CPU/Memory/磁盘与镜像启动；
- 失败与重试、并发空闲、网络传输；
- Verifier、审计、监控和人工审批；
- 最终失败任务也消耗的资源。

模型费用的简化模型：

\[
C_m=\frac{(I-I_c)P_i+I_cP_c+OP_o}{10^6}.
\]

其中 \(I\) 是输入 Token，\(I_c\) 是 Cache Hit Token，\(O\) 是输出 Token，\(P_i,P_c,P_o\) 为每百万 Token 的价格。各厂商可能按 Cache Write/Read、长上下文、批量等采用不同收费规则，实际账单必须以 Provider 返回的 Usage 与官方价格为准。

本章的 [RateCard](../../src/mini_agent/cost_optimization.py) 使用 Decimal 计算，缺少费用信息不会静默按零模型调用处理。

## 23.3 延迟与关键路径

如果两个独立检索分别耗时 100ms 和 110ms，随后合并需要 40ms：

- 串行全部执行：250ms；
- 理想并发关键路径：150ms。

DAG 关键路径可表示：

\[
F(v)=d(v)+\max_{u\in pred(v)}F(u).
\]

这里 \(F(v)\) 为到达节点 \(v\) 完成时的最长路径耗时。项目的 [critical_path](../../src/mini_agent/cost_optimization.py) 对 DAG 做 DFS 与循环检测。

注意：计算关键路径只提供**没有资源竞争和调度开销的理论下界**。真实并发还要考虑 Rate Limit、Worker Slot、网络、锁、冷启动和排队等待。

## 23.4 Context 与 Token 优化

优化路径包括：选择真正相关的文件/证据而非全部聊天记录；对高价值稳定前缀使用厂商支持的 Prompt Cache；避免重复工具输出；对冗余结果压缩但保留来源；按任务复杂度路由不同模型。

压缩不能静默删除关键限制、审批或引用。更短的上下文不是自动更高质量的上下文。应测量原始任务集上的检索覆盖率、引用准确率和 Task Success。

## 23.5 缓存：命中与数据污染的权衡

本章提供 `cache_key(tenant, model, prompt, policy_version, tool_version)`，避免不同租户或权限版本意外共用同一条教学缓存键。

这仅是**逻辑键**，不是安全缓存。生产系统仍需 TTL、数据敏感度、访问权限、版本失效、模型响应依赖、来源日期及内存隔离。缓存答案也必须满足任务的独立验证要求。

错误的缓存优化可能把过期资料、其他租户的证据或失效的工具权限长期保留下来。

## 23.6 模型路由与质量约束

对于简单分类或抽取，小模型可能更经济；复杂推理或跨文件修改可能需要更强模型。但不能依据模型大小直接推断 Task Success。

候选模型路由的比较至少固定：任务集、工具、最大调用预算、Verifier、数据集版本和实际 Provider Usage。先评估安全与质量，再进行成本和延迟排序。

本章 `CostOptimizer` 只接受独立 Host Verifier 提供的布尔验收与证据字符串；在通过预算且通过验收的方案中选择成本最低者，然后用关键路径时延打破同成本平局。**它不自行衡量真实世界模型质量。**

## 23.7 并发并不总是收益

独立步骤可以通过异步工具并行；有依赖的步骤必须按 DAG 调度。加大并发可能增加 Provider 429、数据库争用、上下文整合、工具输出峰值及重复请求。

应与以下基线比较：

1. 串行无缓存；
2. 串行有缓存；
3. 并行工具无缓存；
4. 并行工具有缓存；
5. 模型路由与 Verifier 组合。

对比应同时观察 End-to-End Latency、Task Verified Rate、Cost/Verified Task，而不是只测一个子组件耗时。

## 23.8 执行预算与 Fail Closed

本章 Budget 同时约束：

- `max_cost_usd`；
- `max_duration_ms`；
- `max_model_calls`。

未通过 Host Verifier 的方案即使最便宜，也不会被选中。预算超限的方案即使质量正确，也必须拒绝或显式要求更高预算批准。

真实 Agent Runtime 应将预算检查前移到每次模型/工具调用前，并将第 20 章 Scheduler 的资源配额、实际 Token Usage 和第 21 章重试成本统一记账，避免事后才发现超额。

## 23.10 建议评测指标

| 指标 | 作用 |
| --- | --- |
| Verified Task Success | 真正满足业务验收的比例 |
| Cost per Verified Task | 总成本除以已验证任务数 |
| P50/P95/P99 Latency | 尾延迟和用户体验 |
| Time to First Token | 流式模型首 Token 等待 |
| Tool Queue Wait | 工具/沙箱的排队成本 |
| Cache Hit Rate | 请求和 Token 两个层面的缓存收益 |
| Provider 429/Retry | 并发是否造成过载 |
| Token per Verified Task | 上下文与推理效率 |
| Critical Path Length | 哪些步骤限制完成时间 |

如果已验证任务数为零，Cost/Success 应报告不可计算，不要伪装为零成本。

## 23.11 生产边界

本章不是模型网关，也没有执行真实模型、联网调用或性能基准。所有 Duration 是合成数据；`critical_path` 没有模拟队列争用；`ScopedFixtureCache` 不是有权限隔离的真实数据库；`RateCard` 不含任何实时价格同步。

生产优化需要接入第 22 章 Tracing 的真实 Span、Provider Token Usage、计费账本、缓存实例、授权 Scope 与 Evaluation Framework，并通过 A/B 和任务基准检验回归。

## 23.12 课后习题

1. 扩展价格模型，区分缓存写入费、缓存读取费、Batch API 和长上下文定价。
2. 对第 22 章的 Trace Span 构建 DAG 并计算真实关键路径。
3. 为 Agent Token Budget 设计调用前 Reservation 与调用后 Reconciliation。
4. 加入 Worker Slot 与 Provider Rate Limit，测量理论 Critical Path 与实际 Makespan 的差距。
5. 实现 Token/Cpu/Memory 三维成本约束的 Pareto Frontier。
6. 用真实固定任务集比较小/大模型路由，测量 Cost per Verified Task。
7. 对缓存条目增加 Tenant ACL、Source Expiry、Policy Version、Tool Schema Digest。
8. 构造错误缓存命中的对抗测试，验证不能绕过独立验收。

## 23.13 总结

性能优化必须在真实质量与安全约束之内进行。降低 Token 并不是唯一目标；关键路径、资源排队、重试、验证与错误完成都有成本。本章以可以复现的合成实验演示：**先独立验收，再在符合预算的候选方案中优化成本与时延。**
